# 보안 설계 · 점검 · 한계

이 문서는 개발자 인수인계용 보안 요약이자, 현재 구현된 보안 조치의 점검 결과입니다.

## 적용된 보안 조치

### 1. SQL 인젝션 방지
- **모든** DB 접근은 PDO **Prepared Statement**(바인딩) 사용. 사용자 입력을 쿼리에 직접 붙이지 않음.
- 목록 검색·필터도 파라미터 바인딩. (LIMIT/OFFSET은 정수 캐스팅 후 사용)

### 2. XSS(스크립트 삽입) 방지
- 관리자 화면·이메일 등 **모든 출력은 `htmlspecialchars`(ENT_QUOTES)** 로 이스케이프.
- 입력 단계에서도 `<`, `>` 포함 값은 **거부**(방어 심층화).

### 3. 입력 검증 (`security.php`)
- 성함/연락처/문의내용에 대해: 길이 제한, 제어문자 제거, **HTML(`<>`)·URL(링크) 차단**, 필수값·형식 확인.
- 상담부위는 **허용 목록(18종)만** 통과(임의값 차단).
- 즉, "아무 값이나" 넣으면 통과되지 않고 안내 메시지와 함께 거부됨.

### 4. 과다요청/스팸 방지 (레이트리밋)
- IP당 **10분에 5건** 초과 시 HTTP 429로 차단(`rate_limits` 테이블).
- 폼에 **허니팟** 숨김 필드 — 봇이 채우면 조용히 폐기.

### 5. 관리자 인증
- 세션 기반 로그인, 비밀번호는 `password_hash`/`password_verify`(bcrypt).
- 로그인 시 `session_regenerate_id`(세션 고정 공격 방지), HttpOnly·SameSite 쿠키.
- 관리자 폼은 **CSRF 토큰** 검증. 관리자 페이지는 **캐시 금지** 헤더.

### 6. 파일/서버 보호 (`.htaccess`)
- `config.php`(DB비번), `db.php`, `mailer.php`, `security.php`, `*.sql`, `*.sqlite`, `*.md` 직접 접근 차단.
- 디렉터리 목록 노출 차단, 보안 헤더(X-Content-Type-Options, X-Frame-Options, Referrer-Policy 등).
- 비밀정보(`config.php`)는 저장소에 커밋하지 않음(`.gitignore`). — 단, 로컬 테스트판은 SQLite 데모 설정만 포함(비밀 없음).

## "백엔드가 같은 폴더에 있어서 걱정" — 설명

정적 파일과 백엔드가 한 웹 루트에 있어도, 아래 이유로 안전합니다:
- PHP 파일은 서버에서 **실행**되어 결과(HTML/JSON)만 나가고, **소스코드는 노출되지 않습니다**(정상적인 PHP 호스팅 전제).
- 민감 파일은 `.htaccess`로 직접 접근을 **명시적으로 차단**했습니다.
- DB 비밀번호가 담긴 `config.php`는 접근 차단 + 저장소 미포함.
- 만약을 대비해, **PHP가 실행되지 않는 서버(설정 오류)** 라면 소스가 텍스트로 보일 수 있으므로, 배포 시 PHP가 정상 동작하는지 반드시 확인하세요.

## 한계 — 정직한 안내

- **대규모 DDoS(대량 트래픽 공격)** 는 애플리케이션 코드만으로 완전 방어가 불가능합니다.
  앱 레벨 레이트리밋은 스팸·소규모 남용을 막지만, 대규모 공격은 **호스팅/네트워크 레벨(예: Cloudflare 같은 CDN·WAF)** 이 필요합니다. 운영 시 CDN/WAF 도입을 권장합니다.
- **HTTPS(SSL)** 는 필수 권장입니다. 로그인·개인정보(연락처)가 오가므로 반드시 SSL 적용.
- 관리자 계정 정보(기본 비번)는 **배포 즉시 변경**해야 합니다.
- 개인정보(연락처)를 저장하므로, 실제 운영 시 **개인정보 처리방침·보관기간·접근통제** 등 법적 요건도 함께 검토하세요.
